## 2. 수행 내용
- 검토 반영: `review/2026-W44.md` 는 서명 체크박스 미체크, 코멘트·방향 지시 없음, 10-30 질문 5~7번 답변 비어 있음. 새로 반영할 지시는 없었고, 10-29 위임 답변(실데이터 제공 계획 없음 → 합성으로 진행하되 교체 가능하게 설계)을 그대로 따라 스키마(고정)와 교차 규칙(조정 가능)을 분리했다. D003 상태등급 질문(5번)은 미답이므로 등급 경계는 건드리지 않았다.
- `data/schema/transaction.json` 작성: JSON Schema draft 2020-12, 최상위 13필드·필수 9, `additionalProperties: false`. **1레코드 = 1상품 × 1채널 × 1등록 시도.** 백로그의 5개 축을 `purchase{acquisition_type, buy_price_krw, buy_price_basis, buy_date, quantity}`, `listing{listed_date, listed_price_krw, quantity}`, `channel`(7종), `outcome{status 5종, observed_at, quantity_sold, sold_date, sold_price_krw, channel_fee_krw, shipping_cost_krw}`, 목표변수 `duration_days`·`censored`·`recovery_rate` 로 정의했다. `product_id` 는 D003 외래키, `seller_id` 는 D005 에서 정의할 외래키(패턴만).
- 판매기간 = 등록일→판매완료일. 미판매·중단 레코드는 관측일까지 경과일 + `censored=true` (우측 중도절단). 회수율 = (실판매가×판매수량 − 수수료 − 배송비) ÷ (매입가×등록수량), 위탁이면 null.
- `src/schema/transaction.py` 작성: 스키마 점검 → 레코드 검증 → 교차 규칙(상품 존재, 위탁/매입과 매입가, 수량 순서, 날짜 순서 `acquired ≤ buy ≤ listed ≤ sold ≤ observed ≤ 기준일`, status 별 일관성, 실판매가 ≤ 등록가, 매입가 ≤ 정상가, 기한 경과 후 판매 금지, `duration_days`·`recovery_rate` 재계산 일치) → 경고(정상가 초과 등록, 보유 수량 초과, 허가 품목의 중고앱·SNS 등록, 적자 거래). 상품 파일 없이도(`--products none`) 거래 자체 규칙만으로 검증할 수 있다.
- `data/schema/examples/transaction_examples.jsonl`: status 5종·채널 7종·매입/위탁을 모두 덮는 예시 18건. D003 예시 상품 15건을 참조하고 3개 상품은 채널을 바꿔 2회 등록. **전부 합성(가상) 데이터**이며 목표변수는 스크립트로 정의식대로 계산해 기입했다. 경고 4건은 검증기 동작 확인용으로 일부러 넣었다.
- `tests/test_transaction.py` 26건(정상 6 + 스키마 오류 주입 4 + 교차 오류 주입 13 + 허용 오차 1 + 경고 2). 설계 근거·규칙·한계: `research/2026-11-02/transaction_schema_design.md`.

## 4. 고찰
- 가장 중요한 결정은 중도절단을 1급 필드로 둔 것이다. 장기재고 데이터는 "아직 안 팔린" 레코드 비중이 클 수밖에 없고, 이를 버리면 판매기간이 짧은 쪽으로, 경과일을 그대로 쓰면 긴 쪽으로 편향된다. 회귀 베이스라인(D021·D022)은 `sold` 만 쓰고, 생존분석으로 전체를 쓰는 비교를 Q2 에 추가할 가치가 있다(백로그 후보).
- D003 의 "파생 필드는 스키마에 넣지 않는다" 원칙을 목표변수에는 적용하지 않았다. 라벨은 데이터셋에 박혀 있어야 실험 간 정의가 흔들리지 않는다. 대신 검증기가 재계산해 불일치를 오류로 잡는다.
- D002 의 `regulation=permit` 속성이 처음으로 규칙에 쓰였다(허가 품목 → 개인 간 채널 경고). 채널 적합성 항목(Re-Flow Score)의 하드 제약 후보이지만 법령·플랫폼 약관 근거는 D016 에서 확인해야 한다.
- 예시 수치(판매기간 중앙값 8일, 회수율 1.2)는 가상값이라 어떤 분포도 대표하지 않는다. D008 에서 분포 가정을 따로 세운다. 실제로는 `withdrawn`·`disposed` 와 적자 거래가 더 많을 것으로 예상한다.
- 회수율 분모를 등록수량 기준으로 두어 채널을 나눠 판 경우 레코드별 회수율이 배치 전체와 다르다. 배치 회수율은 집계 단계에서 `product_id`+`buy_date` 로 묶는다.
