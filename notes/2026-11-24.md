## 4. 고찰
- 가장 큰 발견은 **네이버 검색 API 의 조건이 2026년에 바뀌었다**는 것이다. 개발자센터에서 네이버 클라우드 API HUB 로 이관됐고(공식 가이드), 2026-06-25 시행 약관 7.3③ 이 "저장(캐시 행위 포함)·가공" 을 금지하며 특약 2.1 이 결과의 독립 노출을 요구한다. D005 에서 시세 스키마를 "등록가 min/median/max 를 레코드로 저장" 으로 설계했는데, 이 용도가 약관의 "허용 범위" 안인지는 약관에 정의가 없다. 설계 당시 당연히 쓸 수 있다고 본 소스가 서면 확인 사항이 된 셈이고, M4 의 병목은 기술이 아니라 이 한 건의 약관 해석이다. 가이드의 검색 API 목록에 쇼핑이 빠져 있는 것도 확인해야 한다 — API HUB 에 쇼핑 검색이 없다면 구 API 유예 기간(2027-06-30, 2차) 뒤엔 아예 쓸 수 없다.
- 그 결과 **지금 분명하게 자동 수집·저장할 수 있는 시세는 공공데이터(참가격)뿐**이고, 그것도 오프라인 실판매가·신품·16개 소분류다. 의류·가전·디지털·홈·문구·공구 14개 소분류와 **중고 시세 전부**는 clear 소스가 없다. B/C 등급을 used 시세와 비교하기로 한 D003 규칙과 가격경쟁력 항목(D006)은 네이버 허용 또는 중고 플랫폼 제휴 없이는 실데이터에서 계산할 수 없다. 로드맵의 "적정 매입가 산정 자동화율 80%" 가 시세 입력을 전제로 하므로, 이 숫자의 달성 경로가 소스 확보에 걸려 있다는 것을 Q1 보고서(D032)에 써야 한다.
- 참가격은 성격이 다른 소스다(오프라인 판매가 vs 온라인 등록가). 그러나 "정상 소매가 기준선" 으로는 오히려 등록가보다 깨끗하다 — 판매업소·조사일·세일 여부가 있고 출처도 공공이다. D019 를 여기서 시작하면 파이프라인(적재·중복·시계열)을 약관 걱정 없이 만들 수 있고, 네이버가 열리면 소스만 추가하면 된다.
- 크롤링은 사실상 전부 닫혔다. robots 로 막힌 곳(쿠팡·네이버·당근)뿐 아니라 가격비교 사이트도 약관에서 영리 목적 복제를 사전 승낙 사항으로 둔다(에누리 제12조③, 다나와도 같은 유형일 가능성). 3자 스크레이퍼(Apify 등)가 존재하는 것은 허가의 증거가 아니다. 수집 설계는 "API 또는 파일, 없으면 수기" 로 못 박는 게 맞다.
- 판매량(`sold_count_30d`)을 주는 소스가 0개라 D005 에서 자리만 둔 판매속도 외부 신호는 현재로선 채울 수 없다. 검색 트렌드(D017)가 유일한 수요 신호가 될 텐데 그것도 같은 네이버 약관 아래 있다.
- 한계: robots.txt 를 직접 못 읽어 prohibited 4건 중 3건(쿠팡 웹·네이버 쇼핑 웹·당근)이 2차 자료 근거다. 쿠팡 파트너스·11번가·도매꾹은 공식 문서를 못 읽어 한도·조항이 3자 기록이다. 참가격은 품목 수·판매처 유형을 포털 페이지가 안 보여 줘 CSV 를 받아야 안다(이 환경은 포털 파일 다운로드 불가). D019 후보 점수 규칙은 가정이며 수기 priority 와 순서가 대체로 같은지만 확인했다.
