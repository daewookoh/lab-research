## 1. 생성 구조와 순서

M1 테이블 5종(D002~D005) 을 다음 순서로 만든다. 화살표는 참조 방향.

```
categories.yaml (고정)
   └→ seller (N_s)            : 권역·상태·업종·운영채널·주력 대분류 1~3개
        └→ product (N_p)      : 판매자의 주력 대분류 안에서 소분류 선택 → 속성·정상가·수량·보유기간·기한
             ├→ market_price  : 상품당 0~3건, 시세/정상가 비율 r
             └→ transaction   : 상품당 매입 1건 → 채널 등록 1~2건 → 잠재 T + 경쟁 사건 → outcome
```

- 상품→판매자 연결은 v0.1 스키마대로 **거래 레코드의 `seller_id`** 로만 남긴다(상품 스키마에는 없음). 생성기 내부의 product→seller 맵은 `data/synth/v1_meta.json` 에 따로 저장해, 11-12 질문 1(상품에 `seller_id` 추가) 답변에 따라 스키마 v0.2 로 옮길 수 있게 한다.
- 모든 레코드는 기존 검증기(`python -m src.schema.{product,transaction,seller,market_price} --today <기준일>`)를 통과해야 한다. D009 완료 조건에 포함.
- 난수는 `seed`(params) 하나로 고정해 재현 가능하게 한다. 생성기는 params 파일 경로와 seed 를 인자로 받아 v1·v2 를 같은 코드로 만든다.

## 3. 판매기간 승수

T = T_base × Π(승수) 로 뽑는다. 승수는 곱셈이라 log 척도에서 가법이고, D021 선형회귀가 log(T) 를 목표로 삼으면 승수를 그대로 복원할 수 있다(합성 데이터의 "정답" 구조).

| 승수 | 값 | v1 | 비고 |
|---|---|---|---|
| 상태등급 | S 1.0 / A 1.1 / B 1.4 / C 2.0 | 켬 | 같은 가격이면 하자 있는 쪽이 느리다 |
| 가격 | (p / 0.8)^1.0, p = 등록가÷시세 중앙값, p ∈ [0.3, 1.2] | 켬 | 시세보다 싸게 내놓을수록 빠르다 |
| 채널 | open_market 1.0 / own_online 1.3 / offline 1.2 / secondhand 0.9 / **b2b 0.3** / live 0.5 / social 0.8 | 켬 | b2b 는 일괄 매도라 짧다 |
| 브랜드 | major 0.8 / mid 1.0 / minor 1.2 / unbranded 1.4 / unknown 1.3 | v2 | D011 |
| 시즌 | in 0.7 / near 0.9 / neutral 1.0 / off 1.5 (등록월 기준, score_v0 `SEASON_MONTHS` 판정 재사용) | v2 | D011 |

1차 점검에서 가격 탄력 1.5·C 등급 1.8 로 두니 C 의 할인(등록가 계수 0.60)이 등급 승수를 상쇄해 **C 가 S 보다 빨라지는** 결과가 나왔다(run1: C 32.8일 < S 45.3일). 탄력 1.0·C 2.0 으로 바꿔 등급 순서(S 42.9 < A 44.7 < B 46.5 ≈ C 45.5)를 되살렸다. C 가 B 와 비슷한 것은 C 가 short/medium(기본 중앙값이 낮은 묶음)에 많이 배정되기 때문이고, 묶음 안에서 비교하면 C 가 가장 느리다 — D010 EDA 에서 조건부로 확인할 항목.

## 4. 경쟁 사건 → 관측 결과(outcome)

등록일부터 센 일수로 네 사건이 경쟁한다.

| 사건 | 시각 | 결과 status | censored | duration_days |
|---|---|---|---|---|
| 전량 판매 | T | `sold` | false | T |
| 철회 | W ~ Exp(mean 180일 × 채널 계수) | `withdrawn` | true | W |
| 폐기·기부 | D = 잔여기한 − 14일 (기한 없으면 240일) | `disposed` | true | D |
| 관측 | elapsed = 기준일 − 등록일, U(1, 270) | `listed` / `partially_sold` | true | elapsed |

가장 먼저 오는 사건이 결과다. 관측이 먼저면 진행률 (elapsed/T)^1.5 × U(0.6, 1.1) × 등록수량을 판매 수량으로 두고, 1 이상이면 `partially_sold`, 아니면 `listed`. 채널 철회 계수: offline 1.5·b2b 2.0(느긋) / live 0.4·social 0.6(이벤트성, 빨리 접음).

점검 결과(최종, 소분류당 2,000건 단순 시뮬레이션):

```
전체   sold 0.569 / withdrawn 0.230 / partially_sold 0.139 / listed 0.038 / disposed 0.024   중도절단율 0.431
short  sold 0.783  disposed 0.083      medium sold 0.666  disposed 0.072
long   sold 0.597  disposed 0.040      none   sold 0.520  withdrawn 0.268  disposed 0.002
grade C sold 0.422  disposed 0.221 (기한 임박 → 폐기 경로)
sold 만의 duration 중앙값 28.2 / 절단 포함 전체 28.0 / 잠재 T 중앙값 44.3
철회 평균 120 → sold 0.51·절단 0.49 / 240 → 0.60·0.40 / ∞ → 0.72·0.28
```

1차(window 400·철회 240·폐기 365)는 sold 65%·절단 35% 로 "팔린 것" 이 너무 많아 window 270·철회 180·폐기 240 으로 조정했다. D004 고찰("withdrawn·disposed 가 많을 것")에 비하면 아직 sold 가 많다고 볼 수도 있다 — 어느 쪽이 맞는지는 실데이터 없이 정할 수 없어 §8 의 1순위 교체 항목으로 둔다. 철회 평균 하나로 sold 51~72% 가 움직이므로 D010 EDA 에서 이 값을 바꾼 변형 세트를 한 벌 더 만들어 모델 민감도를 볼 가치가 있다.

**편향 재현**: sold 만의 중앙값(28)이 잠재 T 중앙값(44)보다 짧다 — 짧게 팔린 것만 관측 창 안에 들어오는 선택 편향이 합성에서도 생긴다. D021·D022 회귀가 sold 만 쓰면 이 편향을 그대로 학습한다. 생존분석 비교(D004 고찰의 Q2 후보)의 근거.

## 5. 상품·시세·판매자 속성 분포 (요지, 전체 값은 params)

- **상태등급**: expiry 묶음별. none/long = S 45·A 30·B 17·C 8%, medium = 35·28·20·17, short = 30·25·20·25 (기한 임박 → C 가 많음). 점검 결과 전체 S 43·A 30·B 17·C 10%.
- **포장상태**: 등급 조건부(S 는 sealed 90%, C 는 box_damaged·no_box 80%).
- **브랜드 등급**: 대분류별 3프로필 — brand_heavy(FD·BT), mixed(LV·DE·HB), unbranded_heavy(FA·HO).
- **정상가**: lognormal(소분류 중앙값, σ 0.5), 100원 단위 반올림. `list_price_basis` msrp 45·seller_last 30·estimate 15·unknown 10%.
- **수량**: size_class 별 lognormal 중앙값 small 40·medium 20·large 8. unit_count 는 단품 70%, 나머지는 소분류 후보 중 균등.
- **보유기간**(입고→매입): lognormal(150일, 0.6), 최소 30일. 장기재고답게 90일 이상이 대부분.
- **잔여 유통기한**(매입일 기준): short U(45,150) / medium U(90,450) / long U(365,900); C 등급이면 U(10,90)(D003 규칙과 일관). 10~30일 구간이 소량 나와 v0 게이트 G1(≤30일) 사례가 생긴다.
- **시세**: 상품당 0건 10%·1건 45%·2건 30%·3건 15%. 비율 r = 시세÷정상가 ~ lognormal(브랜드별 0.55~0.85, σ 0.2~0.35), [0.2, 1.6] 클립 → 1.2 초과가 소수 나와 `suspect_price` 사례가 생긴다. 관측일 = 기준일 − U(0, 90) → 약 1/3 이 stale(60일 초과). used 관측은 등급 B·C 에서 50~60%, 환산계수 0.55(score_v0 와 동일). `sold_count_30d`·`search_index` 는 각각 50·60% 만 채움(결측 경로 검증용).
- **판매자**: v1 120명. 권역 seoul 30·gyeonggi_incheon 30·chungcheong 10·gyeongsang 15·jeolla 8·gangwon 4·jeju 3%. 상태 active 80·dormant 12·churned 5·**blocked 3%**(G2 사례). 운영 채널 0~3개(채널 회피 규칙 사례). 주력 대분류 1~3개에서 상품을 뽑아 "판매자-카테고리" 군집을 만든다.
- **거래**: 위탁 10%(매입가 0, 회수율 null). 매입 수량 = 보유 × U(0.5, 1). 등록 1건 80%·2건 20%(2건이면 채널 2개로 수량 분할). 등록가 = 정상가 × U(0.45, 0.85) × 등급계수(S 1.0·A 0.95·B 0.8·C 0.6). 매입가 = 등록가 × U(0.35, 0.60). 판매가 = 등록가 × U(0.85, 1.0). 수수료율·배송비는 채널·size 별 상수(score_v0 `SHIP_COST_KRW` 재사용, offline 배송비 0, b2b 1회 발송). → 회수율은 대략 1.0~1.4 에 중심을 두되 수수료·배송비가 큰 소형 저단가 품목에서 1 미만(적자)이 나온다.
- **채널 선택**: 인기 가중치 open 35·b2b 15·own 12·offline 12·secondhand 12·live 6·social 8%. permit 품목은 secondhand·social·live 제외. score_v0 추천 채널은 쓰지 않는다.

## 6. v1 → v2 차이 (D011)

| 항목 | v1 (D009) | v2 (D011) |
|---|---|---|
| 규모 | 상품 1,000 / 판매자 120 | 상품 10,000 / 판매자 800 |
| 승수 | grade·price·channel | + brand·season |
| 등록월 | U(1,270) 균등 | 균등 + 시즌 품목은 시즌 직전 등록 확률 ↑ (시즌성 피처 D027 검증용) |
| 판매자 효과 | 없음 | 판매자별 기재 정확도·반품률 랜덤효과(seller.supply_history 와 연결) |

v2 는 "정답 구조"에 브랜드·시즌 항이 추가되므로 D023 피처 중요도에서 그 항이 복원되는지가 합성 데이터 자체의 검증이 된다.

## 7. D009 구현 지침

- `src/data/synth.py`: `generate(params_path, seed, n_products, n_sellers, reference_date) -> dict[str, list[dict]]` + CLI(`--params data/synth/params_v1.yaml --out data/synth/v1`). 출력은 테이블별 JSONL(검증기 입력 형식) + parquet(모델 입력). `v1_meta.json` 에 product→seller 맵과 **잠재 T·승수 분해**를 함께 저장한다(정답 보관, 모델 평가에서 참조).
- 생성 후 4개 검증기를 기준일로 실행해 오류 0건이어야 완료.
- 생성 직후 점검 스크립트와 같은 요약(묶음 중앙값·상태 비율·절단율·등급 분포)을 `research/<date>/synth_v1_summary.txt` 로 남기고 §4 점검 수치와 비교한다. 차이가 크면(상태 비율 ±5%p 초과) 생성기 버그를 먼저 의심한다.
- 이름(`name`)·`source_text` 는 소분류 `examples` 어휘 + 브랜드명 + 규격 조합 템플릿으로 만든다(과제2 추출 테스트 시드). 브랜드명은 실존 브랜드를 쓰지 않고 "브랜드A" 식 가명.

## 8. 실데이터 수령 시 교체 순서

1. §4 결과 상태 비율·중도절단율 → 철회 평균·폐기 규칙·window 재조정
2. §2 소분류 중앙값·σ → 실측 sold 분포로 교체(소분류당 sold ≥5건인 곳부터), 사전값(`VELOCITY_PRIOR_DAYS`)도 같이 갱신
3. §5 시세 비율 r·등록가 비율 → 실측
4. §3 승수 → D022 LightGBM 이 실데이터에서 추정한 효과로 교체

## 9. 한계

- 모든 숫자가 가정이다. 합성 데이터로 할 수 있는 것은 (1) 파이프라인·검증기·모델 코드가 돌아가는지, (2) 알려진 정답 구조(승수)를 모델이 복원하는지, (3) 중도절단 처리 방식 비교뿐이다. 예측 오차 ±20% 같은 목표 지표 수치는 합성에서 의미가 없다.
- 소분류 안의 이질성(같은 "여성의류"라도 사이즈·시즌·디자인)은 σ 하나로만 표현된다. `attributes` 는 v1 에서 판매기간에 영향을 주지 않는다.
- 판매자와 상품의 상관(기재 정확도가 낮은 판매자의 상품이 느리게 팔림)은 v2 에서야 들어간다.
- 경쟁 사건 모형은 철회를 판매와 독립으로 둔다. 실제로는 "안 팔려서 철회"(종속)가 많을 것이므로 절단이 정보적(informative censoring)일 수 있다 — 생존분석 비교 시 유의.
