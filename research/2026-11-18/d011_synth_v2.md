## 3. D010 이 넘긴 확인 항목 (synth_v2_check.txt §7)

| 항목 | 결과 | 수치 |
|---|---|---|
| (A) 오라클 OLS(잠재 T) 승수 복원 최대 \|log 차이\| ≤ 0.05 | **경계선 — 기준 그대로는 FAIL(0.055), 판매자 효과를 모형에 넣으면 PASS(0.044)** | seed 4개: 판매자 효과 오차항 0.055 / 0.047 / 0.066 / 0.058, 판매자 더미 0.044 / 0.040 / 0.055 / 0.043 |
| (B) 권역 가짜효과 소멸 | **PASS** | KM 중앙값 범위 v1 39~69일 → v2 41~55일; 소분류 통제 권역 계수 최대 \|0.083\|(v1 0.265). 남은 계수는 판매자 랜덤효과의 권역 평균(chungcheong −0.058, jeolla +0.071)과 같은 크기·부호 |
| (C) 소분류 n ≥ 100 | **PASS** | 전체 행 min 225 / 중앙값 371 / max 979, sold 행 min 113(v1 은 16 / 10) |

(A) 해석: 정답 승수 16개를 n≈12,000 으로 추정할 때 se 가 0.018~0.036 이므로 "최대 |차이| ≤ 0.05" 는 16개 계수의 최대 오차가 약 2se 안에 들라는 요구다. 판매자 효과(sd 0.25)가 오차항에 남으면 4 seed 모두 0.047~0.066 으로 경계에 걸리고, 판매자 더미를 넣으면 4 seed 중 3개가 0.05 안이다. 가장 큰 오차는 매번 다른 항(grade=B, brand=unknown, ch=b2b, ch=live)이어서 **체계적 편향이 아니라 표본 노이즈**로 본다. 생성기 결함 신호(같은 항이 같은 방향으로 틀림)는 없다. 기준을 "≤ 2.5 se" 또는 "판매자 효과 포함 모형에서 ≤ 0.05" 로 두는 것이 맞다고 보며, 노트 6번에 확인 요청.

## 4. v2 신규 항의 복원 (synth_v2_check.txt §2, fig1)

공통 모형: log T ~ 소분류 FE + 등급 + 채널 + 브랜드 + 시즌 + log(p/0.8). 시즌의 `neutral` 은 소분류(seasonality 없음)로 결정되어 소분류 FE 와 완전 공선이므로 **near_season 대비 in/off 만 식별**된다(정답 in −0.252 = log 0.7/0.9, off +0.511 = log 1.5/0.9). 처음에 neutral 을 기준으로 두고 돌렸더니 시즌 계수가 +3.5 로 터졌는데 이것은 공선성(최소노름 해)이지 생성기 문제가 아니었다 — D021·D027 에서 시즌 피처를 만들 때 같은 함정이 있다.

| 추정 | 최대 \|차이\| | 가격 탄력(정답 1.0) | 항별 최대 \|차이\| grade / ch / brand / season / p |
|---|---|---|---|
| (a) 오라클 OLS, 잠재 T | 0.055 | 0.972 | 0.055 / 0.049 / 0.005 / 0.04 / 0.03 |
| (b) sold 만 OLS | 0.291 | 0.741 | 0.16 / 0.29 / 0.06 / 0.04 / 0.26 |
| (d) 로그정규 AFT(절단 반영) | 0.056 | 0.955 | 0.06 / 0.04 / 0.03 / 0.04 / 0.04 |

- 브랜드 4개·시즌 2개 계수는 오라클에서 0.005·0.04 안으로 복원됐고, AFT 도 0.03·0.04. 브랜드는 시세 비율 r 과 얽혀(major r 0.85 … unbranded 0.55 → 평균 p 0.71 vs 0.98) 조건 없는 KM 중앙값은 28 → 79일로 정답 승수(0.8 → 1.4)보다 훨씬 벌어진다(§6). p 를 통제해야 브랜드 승수가 맞게 나온다 — D010 의 등급·가격 상쇄와 같은 구조.
- **sold-only OLS 의 0 쪽 축소는 v1 과 같은 양상**(가격 탄력 0.74 — v1 0.64, b2b 승수 0.30 → 0.40 추정 — v1 0.39, C 등급 2.0 → 1.70 — v1 1.63). n 이 10배가 돼도 줄지 않는 **편향**임이 분명해졌다. AFT 는 n 이 10배가 되면서 v1 0.290 → **0.056** 으로 오라클과 같은 수준이 됐다. v1 의 AFT 오차 0.29 는 social_market(n=79) 한 항의 표본 노이즈였음이 확인된다.
- 판매자 랜덤효과: 오라클 OLS 에 판매자 더미 664개를 넣으면 정답 u 와 상관 0.656(RMSE 0.29, 정답 sd 0.25), 거래 ≥20건 판매자(214명)만 보면 **0.843**(fig3). 판매자당 거래가 적은 꼬리(판매자당 거래 중앙값 13건, 평균 18건)에서는 더미가 노이즈라 D022 에서 판매자 ID 를 그대로 피처로 쓰면 과적합한다 — 축소 추정(혼합모형 BLUP) 또는 아래 대리 피처가 필요하다.

## 5. 시즌 등록월 편향·판매자 대리 피처 (fig2, fig4, §4~5)

- 시즌 품목 9,016행 중 near_season 51.3% / in 27.0% / off 21.7%. near 가 많은 것은 35% 강제 + 관측창(2/21~11/17)에서 near 달 비중이 원래 큰 소분류(여름·겨울 품목의 4·5·9·10월)가 많아서다. 등록월 분포 자체는 비시즌 품목과 월 단위로 ±4%p 차이(7·8월 ↑, 3·4·5월 ↓)라 fig4 에서 보이지만 약하다. 시즌 피처 검증(D027)에는 충분하지만, 등록월만으로 시즌 품목을 알아맞히는 과제에는 신호가 작다.
- 단일 소분류(FD-HF-SUP, holiday)의 KM 중앙값 in 26 / near 28 / off 49일(fig2) — 정답 0.7 / 0.9 / 1.5 방향과 일치. 소분류를 섞은 KM(§4)은 near 48 > in 44 로 뒤집히는데 시즌 품목이 느린 소분류(패션·가전)에 몰려 있기 때문이다.
- 판매자 프로필별 u 평균 −0.275 / −0.010 / +0.266, accurate 비율 0.73 / 0.59 / 0.37, 판매자 단위 corr(u, accurate 비율) = −0.49. 거래 단위로 "그 판매자의 accurate 배치 비율" 을 피처로 넣으면 계수 −0.66±0.04(오라클), −0.64±0.04(AFT) — **실데이터에서 판매자 ID 대신 쓸 수 있는 공급 이력 피처**가 생성기 정답 구조 안에 들어갔다. 다만 u 의 분산 중 이 피처가 설명하는 몫은 작다(잔차 sd 0.829 → 0.818, 판매자 더미는 0.795).

## 6. 하지 않은 것 / 한계

- 설계 §6 의 "반품률 랜덤효과" 는 넣지 않았다(철회 W 는 v1 과 같이 채널 의존만). 판매자별 철회 경향은 v2.1 로 미룸.
- 경과일 꼬리: 배치 매입일을 ref − (U(1,270) + U(1,14)) 로 뽑고 gap 을 다시 뽑는 v1 규칙 때문에 elapsed 가 최대 281일(설계 상한 270)까지 나온다. v1 부터 있던 것이고 D009 노트의 "경과일 분포 버그 수정" 뒤에도 남은 꼬리다. v1 재현성을 깨지 않으려고 고치지 않았다 — v2.1 항목으로 백로그에 추가.
- 시즌 승수는 등록월 한 시점으로만 판정한다. 실제로는 등록 후 시즌에 들어가면 빨라져야(시간 변동 공변량) 하지만 v2 는 그 구조가 없다. D027 시즌 피처는 "등록월 기준" 과 "판매 중 시즌 도달" 을 구분해 설계해야 한다.
- 승수 정답 구조는 여전히 로그 가법이라 트리 모형(D022)에 유리하지 않은 세팅이다(상호작용 없음). 상호작용(예: 시즌×소분류)은 실데이터를 보고 넣는다.
- v2_meta.json.gz 에 거래별 정답(잠재 T·승수 분해·u)이 전부 있으므로, 모델 코드가 `latent_*` 열을 입력으로 쓰지 않도록 D014 분할 코드에서 열을 명시적으로 제외해야 한다.
