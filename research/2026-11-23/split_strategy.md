## 1. 왜 시간 기준인가

판매기간은 **등록일에 시작해 관측 기준일에 잘리는** 우측 중도절단 자료다. 무작위 K-fold 는 두 가지 누출을 만든다.

| 누출 | 무작위 분할에서 생기는 일 | 시간 분할 규약 |
|---|---|---|
| 라벨 누출 | 기준일 이후에야 알 수 있는 결과(판매 완료·판매기간)로 학습 | train 라벨을 cutoff 에서 **관리적 절단**(as-of censoring, §2) |
| 피처 누출 | 정답에서 만든 열, 결과 열, test 거래가 섞인 집계(소분류 중앙값·D_ref) | 금지 목록(§3) + 집계는 as-of train 으로만(`train_group_stat`) |
| 분포 이동 무시 | 시즌·판매자 구성 변화가 평가에 안 보임 | 롤링 cutoff 로 지표의 범위를 같이 보고(§5) |

D012 에서 "등록 시점 평가"가 누출 있는 기준일 평가보다 **더 좋았던**(C .596 vs .580) 것과 같은 원칙 — 실데이터 베이스라인도 "그때 알 수 있던 정보" 로 재야 한다.

## 2. 분할 정의 (`time_split`)

```
cutoff 날짜 c, 관측 기준일 O(= observed_at 최대), 최소 추적 기간 H
train = 등록일 < c           라벨: 종료일 ≥ c 이면 time = c − 등록일, event = 0  (as-of 절단)
                                   종료일 < c 이면 원래 라벨
test  = c ≤ 등록일 ≤ O − H   라벨: O 시점의 원래 라벨(sold → 판매기간 / 그 외 → 등록~종료일, 절단)
```

- **as-of 절단**이 핵심이다. "등록일 < c" 만으로 train 을 자르면 c 이후에 팔린 결과가 train 라벨에 들어간다(라벨 누출). cutoff 07-01 에서 train 5,104건 중 1,882건(37%)이 c 이후에 종료되어 as-of 절단된다 → train 절단율 .33 → .56.
- **H(최소 추적 기간)** 은 결과와 무관하게 "충분히 오래된 등록" 만 평가하는 규칙이다. `observed_at − listed_date ≥ H` 로 거르면 안 된다(일찍 팔린 행은 남고 안 팔린 행만 빠져 빠른 쪽으로 편향). 등록일 상한으로만 거른다.
- `asof_train=False` 는 라벨 누출 대조군(점검 A 전용). 모델 학습에는 쓰지 않는다.
- 종료일은 합성 v2 에선 `observed_at`(sold 면 판매일, 아니면 마지막 관측일 — 전 행 `duration_days` 와 일치 확인). 실데이터에선 판매일·철회일·스냅샷일 중 무엇인지 확인해야 한다(11-17 질문 2, 미답).

## 3. 피처 금지 목록 (`forbidden_columns`, `assert_no_leakage`)

| 구분 | 열 | 이유 |
|---|---|---|
| 정답(합성 전용) | `latent_*`, `ref_*`, `total_ref` | 생성기 잠재변수·D012 누출 대조 점수. 실데이터엔 없음 |
| 결과 | `status`, `observed_at`, `quantity_sold`, `sold_price_krw`, `channel_fee_krw`, `shipping_cost_krw`, `duration_days`, `censored`, `recovery_rate`, `season_state` | 등록 이후에 결정. 라벨·평가 전용. `season_state` 는 생성기의 시즌 정답 라벨(D011 노트)이라 금지 — 모델은 `listed_month` 에서 스스로 만들어야 함 |
| 식별자 | `transaction_id`, `product_id` (`allow_ids=True` 로 허용 가능) | 과적합. `seller_id` 는 허용하되 타깃 인코딩은 as-of train 으로만 |

v2_flat 54열 + `total` 에 적용하면 **금지 26열 / 허용 29열**(`split_check.txt` §D). 허용 열 중 주의할 것: `buy_price_krw`·`buy_date`·`acquisition_type` 은 판매기간 모델(과제 1)에선 등록 시점 정보라 허용이지만 매입가 산정(과제 2)에선 타깃이고, `channel`·`listed_price_krw` 는 운영자 결정이라 채널 추천 모델에선 타깃이다. 모델별 금지 열은 각 모델 스크립트가 `assert_no_leakage` 에 추가로 넘긴다.

|---|---|---|---|---|---|
| train as-of 절단(규약) | −.308 ~ −.322 | 47~48일 | .592 | .132 | .764 |
| train 미래 결과 사용(누출) | −.301 ~ −.331 | 45~48일 | .592 | .133 | .762 |

as-of 절단으로 train 절단율이 .33 → .58 로 오르는데도 AFT 계수·test 지표는 누출 대조군과 같다. 합성 v2 는 정답 구조가 시간에 따라 바뀌지 않고 AFT 가 절단을 올바르게 다루므로 **정보가 줄어도 편향이 생기지 않는다**는 확인이다. 즉 as-of 절단은 "성능을 깎는 보수적 규칙" 이 아니라 공짜에 가깝고, 실데이터에서 둘이 다르면 그것이 바로 누출의 크기다. D013 기준값(07-01, 누출 train: .134/.757/.594)은 as-of 로 바꿔도 .135/.754/.594 — **D013 기준값은 그대로 유효**.

cutoff 를 뒤로 보낼수록 ±20% 는 .145 → .110, 절단적중은 .712 → .841 로 움직이는데 모델이 달라진 게 아니라 **test 절단율이 .46 → .63 으로 오르기 때문**이다(최근 등록분은 관측이 짧다). sold 적중률과 절단 적중률은 분할 날짜에 따라 반대 방향으로 움직이므로 지표 하나만 보고 분할을 고르면 안 된다 — C 는 .589~.596 으로 안정.

### B. 최소 추적 기간 H (cutoff 07-01, Fig 2)

| H | test n | 절단율 | 절단 행 구성 | 절단 행 관측일 중앙값 | v0: ±20% | 절단적중 | C | log 편향 |
|---|---|---|---|---|---|---|---|---|
| 0 | 6,876 | .499 | partially_sold 1,367 / withdrawn 1,312 / listed 745 | 26일 | .135 | .754 | .594 | +.78 |
| 30 | 5,511 | .417 | withdrawn 1,215 / partially 855 / listed 223 | 41일 | .145 | .633 | .595 | +.72 |
| **60** | **4,095** | **.371** | withdrawn 986 / partially 438 / listed 94 | 49일 | .162 | .554 | .595 | +.67 |
| 90 | 2,694 | .343 | withdrawn 681 / partially 214 / listed 29 | 42일 | .156 | .574 | .595 | +.63 |
| 120 | 1,117 | .354 | withdrawn 300 / partially 88 / listed 7 | 41일 | .143 | .567 | .593 | +.59 |

예상 밖의 결과 두 가지.

1. **절단 적중률이 H=0 에서 부풀려져 있다.** H=0 의 절단 행은 관측 14~26일짜리 `listed`·`partially_sold` 가 2,100건이라 T̂≈48일이면 거의 자동으로 맞는다. H≥60 이 되면 절단 행의 대부분이 **철회(withdrawn)** 이고 관측일 중앙값이 49일이라 "T̂ > 관측일" 은 동전 던지기(.55)가 된다. 즉 절단 적중률은 H 가 충분히 크면 사실상 "모델이 판매자 철회 시점보다 길게 예측했는가" 를 재는 것이지 판매 예측 품질이 아니다. 철회는 판매와 다른 과정(판매자 사정)이라 이 지표의 분모를 바꿔야 한다(§6, 질문 1).
2. **H 를 늘려도 sold 행 log 편향이 +.6 아래로 안 내려간다.** H=120 까지 올려도 +.59 — 이것은 관측이 짧아서가 아니라 σ≈1.1 인 로그정규에서 팔린 것만 보면 중앙값이 절반으로 보이는 선택 편향 자체다(D013 Fig 2 와 같은 말). 따라서 H 는 "편향을 없애는" 규칙이 아니라 "최근 등록분의 극단적 절단을 피하는" 규칙이고, 60 이상에서 지표가 평평해지므로 **H=60** 이 n 손실(6,876 → 4,095)과 안정성의 타협점이다. C 는 H 에 거의 무관(.593~.595)해서 모델 선택 지표로서 다시 확인됐다.

## 5. 규약 (D021 이후 모든 판매기간 모델에 적용)

1. **주 평가 P1**: cutoff 2026-07-01, train as-of 절단, test H=60 → 합성 v2 에서 train 5,104 / test 4,095(등록 07-01~09-19). 기준값: 소분류 KM 중앙값 ±20% .154 / 절단적중 .589 / C .598, v0 AFT .162 / .554 / .595.
2. **안정성 P2**: 롤링 cutoff 05-01·06-01·07-01·08-01(확장 창), H=60. 지표를 평균[최소, 최대]로 보고. 모델 선택은 **4 fold C 평균**(D013 규약과 일치), fold 간 순위가 뒤집히면 보고.
3. **D013 연속성 P3**: cutoff 07-01, H=0 — D013 표와 이어지는 숫자. 절단적중은 P3 에서만 .75 수준이고 P1 에선 .55 수준임을 항상 병기.
4. 집계 피처(소분류 KM 중앙값, D_ref, 판매자 타깃 인코딩)는 **as-of train 으로만**(`train_group_stat`, min_n 20). 모델 입력 열은 `assert_no_leakage` 를 통과해야 하고, 모델별 추가 금지 열(§3)을 스크립트에 명시.
5. CI 는 판매자 클러스터 부트스트랩 200회 이상. 보고 양식: "합성/실제, seed, cutoff, H, n_train/n_test, 절단율" 을 수치마다 적는다.
6. 하이퍼파라미터 탐색(D022)은 train 안에서 다시 시간 분할(예: train 의 마지막 달을 validation, 역시 as-of) — test 는 한 번만 본다.
7. 실데이터 적용 시 바꿀 것: cutoff 는 데이터 수령 후 "최근 3개월을 test" 로 잡고, H 는 실데이터 판매기간 중앙값에 맞춰 재검토(합성은 중앙값 ≈ 50일이라 60; 실데이터 중앙값이 20일이면 H=30 으로 충분).

## 6. D013 에 되돌려야 할 것 / 열린 질문

- **절단 적중률의 분모**(§4-B-1): 현재 "모든 절단 행" → 후보 (a) `listed`(아직 판매 중, 관리적 절단)만 — 합성 H=60 test 에서 94건뿐이라 CI 가 넓음, (b) 철회를 별도 지표 "철회 전 예측 적중" 으로 분리, (c) 철회·부분판매는 경쟁 위험(competing risk)으로 보고 판매 누적발생함수(CIF)로 평가. 합성에선 (c) 가 가장 정직하지만 구현 비용이 있어 D021 전에 (a)+(b) 로 먼저 가고 (c) 는 백로그 추가(D021b 제안).
- `partially_sold` 를 절단으로 둘지 "부분 사건" 으로 둘지. v2 test H=0 에서 1,367건(20%)이라 결정이 지표를 크게 움직인다. 거래 스키마(D004)의 정의대로 현재는 절단.
- 11-20 질문 15(a) "절단 적중 ≥ 70%" 는 H=0 기준 숫자였다. H=60 에선 오라클도 .55 근처일 가능성이 크므로 판정 기준은 분모 결정 후 다시 제안한다.

## 7. 한계

- 전부 합성. 합성 v2 는 정상(stationary) 구조라 분할 날짜에 따른 모델 성능 이동이 없다 — 실데이터에서 롤링 fold 의 범위가 넓으면 시즌·정책 변화를 의심.
- 오라클 천장은 오늘 계산하지 않았다(D013 §7 과 같은 방식으로 P1 에 추가 가능, 10분).
- 등급 F1·채널 Top-1 의 분할 적용은 D024·D025 에서. 분할 코드는 공통이라 추가 작업 없음.
- `time_split` 은 등록일 기준이다. "매입 판단 시점" 기준(11-19 질문 3)으로 바꾸려면 `listed_col` 만 바꾸면 되지만 D_ref 류 집계는 그 시점으로 다시 만들어야 한다.
