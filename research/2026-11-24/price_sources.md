# D016 — 시세 데이터 소스 조사: 공개 API·크롤링 가능 채널 목록 + 이용약관 확인

- 작성: 2026-11-24, AI 연구보조(Claude) 초안 — 연구책임자 승인 전 (draft)
- 산출물: `data/collect/price_sources.yaml`(소스 목록 v0.1, 15개), `src/collect/sources.py`(검증·커버리지·순위), `tests/test_sources.py`(8건), `price_sources_check.txt`(실행 결과)
- 전제: 실제 거래 데이터 없음(보류 질문 Q1). 오늘은 데이터가 아니라 **소스와 약관**을 조사한 것이라 합성 데이터도 쓰지 않았다. 수치는 전부 "소스 목록에 대한 집계" 다.
- 법률 자문이 아니다. 약관 요지는 원문을 읽고 옮긴 것이며, 수집 착수 전 연구책임자(필요하면 법무) 확인이 필요하다.

## 1. 목적과 범위

M4(시세·검색트렌드 수집 파이프라인)의 첫 단계. `market_price.json`(D005)의 `source.platform` 은 "D016 소스 조사 후 enum 으로 고정 예정" 으로 비워 두었고, Re-Flow Score 의 가격경쟁력·시장수요 항목(D006·D007)과 매입가 역산(M12)이 전부 시세 입력에 기대고 있다. 오늘은 (1) 어떤 소스가 있는지, (2) 각 소스를 **자동으로 수집해 저장소에 축적하는 것**이 약관·robots.txt 상 허용되는지, (3) 소분류 30개 중 몇 개를 덮는지, (4) D019 수집기 v1 이 어느 소스부터 시작해야 하는지를 정한다. 검색 트렌드(네이버 데이터랩 쇼핑인사이트 등)는 D017 로 넘긴다.

"허용" 의 기준은 우리 용도다 — 조회 결과를 화면에 보여주는 것이 아니라, 상품별·관측일별 레코드로 **저장해서** 모델 학습과 점수 계산에 쓴다. 많은 API 가 "그대로 노출" 용도만 허용하므로 이 구분이 결과를 가른다.

## 2. 조사 방법과 한계

- 웹 검색으로 후보를 모은 뒤, 공식 문서·약관·공공데이터포털 페이지를 직접 읽었다(읽은 URL 은 YAML `evidence` 에 소스별로 적음). 읽은 1차 자료: 네이버 클라우드 API HUB 가이드 4쪽 + NAVER API 서비스 이용약관 PDF(2026-06-24 판), 공공데이터포털 4쪽, 에누리 이용약관. 2차 자료(블로그·기사·3자 README)는 YAML 과 아래 표에 "(2차)" 로 표시했다.
- **읽지 못한 것**: 쿠팡 이용약관(접근 실패), 쿠팡 파트너스 공식 API 문서(partners.coupang.com, 미열람), 네이버 API HUB 의 API 명세 페이지(api.ncloud-docs.com, 이 환경의 외부 접근 승인 만료), 11번가 OpenAPI 문서, 다나와·번개장터·중고나라·도매꾹·지마켓 약관.
- **robots.txt 12개 직접 조회 실패** — 이 실행 환경은 대화에 등장하지 않은 URL 을 가져올 때 사람 승인이 필요한데 무인 실행이라 승인이 나지 않았다. robots 내용은 전부 2차 자료(디지털마케터 2026-10-04 분석, 바이라인네트워크 2026-04-27 기사)다. **D018 설계 전에 네트워크가 열린 환경에서 `robots.txt` 를 직접 받아 YAML 을 갱신해야 한다**(D018 선행 작업으로 백로그에 적음).
- 한 번 읽은 페이지의 문구만 적었고, 기억에 의존한 항목(구 네이버 쇼핑 검색 응답 필드, 도매꾹 API 존재, 지마켓 API 부재)은 "기억 기준, 미확인" 으로 표시했다.

## 4. 약관에서 확인한 핵심 조항

### 4.1 네이버 (API HUB, 2026-06-24 판 약관, 2026-06-25 시행)
- 2026년 중 검색 API 가 네이버 개발자센터에서 **네이버 클라우드 API HUB 로 이관**됐다(공식 가이드 확인; 이관일 9-07·구 센터 신규 신청 중단 7-31·유예 2027-06-30 은 블로그 2차). 인증 헤더가 `X-Naver-Client-Id/Secret` 에서 `X-NCP-APIGW-API-KEY-ID / X-NCP-APIGW-API-KEY` 로, 도메인이 `naverapihub.apigw.ntruss.com` 으로 바뀐다. 요금은 종량제이나 **"한시적으로 무료"**, 유료 전환 시 사전 공지. 한도는 NAVER 검색 카테고리 **합산 월 775,000건**(일 단위 아님), 키당 50 RPS, 무료 기간 증량 불가. 흔히 말하는 "일 25,000건" 은 공식 가이드에 없다.
- 우리 용도와 충돌하는 조항: 일반조건 **7.3③** "API 제공 정보를 허용 범위를 넘어 무단으로 복제, 저장(캐시 행위 포함), 가공, 배포 … 금지", "기타 각 API 의 제공 취지나 목적에 맞지 않게 API 제공 정보를 저장하거나 이용하는 행위" 금지. 특약(검색 API) **2.1** 검색결과를 "독립적으로 노출" 해야 하며 앞·뒤·중간에 다른 내용 삽입·왜곡 금지. **7.2②** 애플리케이션 사용자로부터 대가 수취 금지. 7.3④ 결과화면과 광고 동시 노출 금지. 7.3⑫ 자동화 프로그램 접속·주기적 접속 금지(크롤링에 해당).
- 해석(법률 자문 아님): 검색 결과의 min/median/max 를 레코드로 저장해 모델에 쓰는 것은 "저장·가공" 에 해당할 여지가 크다. 다만 "허용 범위" 와 "제공 취지" 가 어디까지인지 약관에 정의가 없다. **네이버 클라우드에 용도를 밝히고 서면 확인을 받기 전엔 저장 용도로 쓰지 않는 것**이 안전하다. 조회 시점에만 쓰고 저장하지 않는 방식(점수 계산 시 즉시 조회, 레코드엔 집계값만)도 7.3③ 의 "가공" 에 걸릴 수 있어 같은 확인이 필요하다.
- 추가 미확인: 공식 사용 가이드(apihub-use)의 NAVER 검색 API 목록이 뉴스·블로그·지역·지식iN·책·카페·백과사전·이미지·전문자료·웹문서이고 **쇼핑이 빠져 있다.** API HUB 에서 쇼핑 검색을 제공하는지 자체를 명세 페이지에서 확인해야 한다. 안 되면 이 소스는 2027-06-30(2차) 까지의 구 API 유예 기간에만 쓸 수 있는 셈이다.

### 4.2 에누리 (이용약관 2026-08-06 시행) — prohibited
제12조③ "이용자는 회사의 서비스를 이용함으로써 얻은 정보를 회사의 사전 승낙 없이 복제, 송신, 출판, 배포, 방송 기타 방법에 의하여 영리목적으로 이용하거나 제3자에게 이용하게 하여서는 안됩니다." 제10조(사) "회사의 서비스를 이용자의 영리 목적으로 활용하는 행위" 금지. 크롤링·API 조항은 없지만 영리 목적 복제·이용 자체가 사전 승낙 사항이므로 제휴 없이는 제외. 다나와도 같은 유형의 조항이 있을 가능성이 높아 약관 확인 전 보류.

### 4.3 쿠팡 — 웹 prohibited / 파트너스 API conditional
- 사이트 약관은 접근 실패로 못 읽었다. robots.txt 는 2차 자료 기준 `*` 전체 차단이라 크롤링은 제외.
- 파트너스 Open API(`/v2/providers/affiliate_open_api/apis/openapi/v1/products/search`)는 제휴 수익 프로그램용이다. 3자 README 기준 호출당 최대 10건, 응답 `productPrice`·`productName`·`isRocket`·`isFreeShipping`·`productUrl`. 한도는 "분당 50회" 와 "시간당 30회 초과 시 24시간 정지, 3회면 계정 정지" 가 한 문서 안에서 상충한다. 파트너스 약관의 데이터 저장·용도 조항을 못 읽었고, 제휴 링크 게시 목적 외 사용(시세 DB)이 허용되는지가 핵심이라 conditional.

### 4.4 공공데이터 — clear
- **한국소비자원 참가격**(price.go.kr 기반) 생필품 가격정보: 파일(CSV, 월간, 로그인 없이 다운로드)과 GW 오픈API(활용신청). 이용허락 "제한 없음"/출처표시. 판매업소명·조사일·판매가격·제조사·세일/1+1 여부. 품목 수·판매처 유형(대형마트/SSM/전통시장)·조사 주기는 포털 페이지에 미기재 → CSV 를 받아 세어야 한다(이 환경은 포털 파일 다운로드 불가). 오프라인 **실판매가**라 온라인 등록가와 성격이 다르지만, 가공식품·세제·위생·화장품(헤어바디)·기저귀 등 우리 FD·LV·BT·HB 대분류의 "정상 소매가 기준선" 으로 바로 쓸 수 있다.
- 경북 밥상물가 API: 식료품·경북 한정, 보조.
- 용인시 시장마트가격(2018년 이후 미집계, 1회성) — 제외.

### 4.5 robots.txt 로 본 국내 플랫폼 기조 (전부 2차)
쿠팡·네이버 쇼핑·당근은 전면 또는 AI 봇 차단, 11번가·롯데온·올리브영·무신사·지마켓은 AI 검색봇을 선별 허용(학습용 봇은 차단, 3~5초 대기). "검색 응답용 허용" 은 사용자 요청 시 열람을 허용한다는 뜻이지 주기적 수집·저장 허가가 아니다. 어느 쪽이든 **우리 수집기는 로봇으로 접근하는 것이므로 `*` 규칙과 약관을 따라야 한다**.

## 5. 커버리지 (`src/collect/sources.py` 실행, `price_sources_check.txt`)

```
소스 15개 — 검증 오류 0건 (channel enum·platform 형식·evidence·prohibited→priority 0 규칙)

clear 만                     자동(api·file) 소스로 덮이는 소분류: 신품 16/30  중고  0/30   (수기 포함 시 30/30)
clear+conditional           자동: 신품 30/30  중고 30/30                                   (네이버 API HUB 허용 가정)
```

- **지금 당장 합법적으로 자동 수집해 저장할 수 있는 시세는 참가격뿐**이고, 그것도 FD·LV·BT·HB 16개 소분류의 오프라인 실판매가다. 의류·가전·디지털·홈·문구·공구(FA·DE·HO, 14개 소분류)는 clear 자동 소스가 없다.
- **중고(used) 시세는 clear 자동 소스가 0개**다. B/C 등급 상품(D003 에서 used 시세와 비교하기로 한 등급)의 가격경쟁력 항목은 네이버 API HUB 허용 여부 또는 번개장터·중고나라 제휴에 달려 있다.
- 네이버 API HUB 쇼핑 검색 하나가 허용되면 신·중고 30/30 이 된다. 그래서 이 한 건의 약관 확인이 M4 전체의 병목이다.
- `sold_count_30d`(판매량)를 주는 소스는 15개 중 0개. D005 에서 자리만 둔 판매속도 외부 신호는 현재로선 채울 수 없다.

D019 후보 순위(점수 규칙은 가정: 법적 안전 3/1/0 + 자동화 2 + 커버 대분류 ×0.3 + 확인 1 + 0.5): `price_go_kr` 7.7 > `manual_search` 7.1 > `gyeongbuk_price` 6.8 > `naver_apihub_shop` 6.6 > `coupang_partners` 5.6 > `st11_openapi`·`domeggook` 4.6 > 크롤링 후보 ≤2.6.

## 6. 결론·권고

1. **D019 수집기 v1 은 참가격 파일(CSV 월간 + GW API)로 시작**한다. 1개 소스·10개 품목 조건에 맞고 약관이 분명하다. 품목은 FD·LV·BT·HB 소분류의 `examples` 어휘(감자칩·캔커피·액체세제·물티슈·샴푸·기저귀 등)에서 참가격 상품명과 매칭되는 10개를 고른다. `market_price` 레코드는 `channel=offline_store, platform=price_go_kr, collected_by=api, match_type=similar|exact, price_type` 은 실판매가임을 `notes` 에 표시.
2. **네이버 API HUB** 는 (a) 쇼핑 검색이 API HUB 에 있는지 명세 확인, (b) 네이버 클라우드에 "연구용 시세 레코드 저장" 용도 서면 문의 — 두 가지가 끝날 때까지 수집기에 넣지 않는다. 허용되면 1순위로 교체(전 카테고리·신중고·min/median/max 를 한 번에 줌).
3. **쿠팡 파트너스**는 파트너스 가입(사업자)과 약관 원문 확인 후 판단. 호출당 10건이라 분포가 아니라 상위 10개 등록가만 얻는 한계가 있다.
4. 크롤링은 robots 로 막힌 쿠팡·네이버·당근, 약관으로 막힌 에누리를 제외하고도 **unknown 6개는 전부 약관·robots 직접 확인 전 보류**. 3자 스크레이퍼가 존재한다는 것은 허가의 근거가 아니다.
5. `source.platform` enum 제안(prohibited 제외 + other): `bunjang, coupang_partners, danawa, domeggook, gmarket_auction, gyeongbuk_price, joongna, manual_search, naver_apihub_shop, price_go_kr, st11_openapi, other`. 스키마 반영은 승인 후 D018 에서.
6. 수기 입력 경로(`manual_search`)는 파일럿 실데이터의 시세 열을 채울 현실적 방법이므로 D018 에서 입력 폼(최소 필드: 검색어·플랫폼·n·min/median/max·배송비 포함 여부)을 설계에 넣는다.

## 7. D017·D018 에 넘기는 것

- D017(검색 트렌드): 네이버 데이터랩(검색어 트렌드·쇼핑인사이트)도 API HUB 로 이관됐고 각 월 50,000건 한도(공식 가이드). 같은 약관 7.3③ 이 적용되므로 트렌드 지수 저장도 같은 확인이 필요하다 — D017 에서 함께 문의.
- D018 선행: 네트워크 열린 환경에서 robots.txt 12개 직접 조회 → YAML 갱신(백로그 D018 설명에 추가). 참가격 CSV 를 받아 품목 수·판매처 유형·조사 주기 집계.
- D018 설계 입력: 참가격은 월 1회 파일, API 는 품목/업체 ID 기준 조회 → "월간 파일 적재 + 변경분 API 보강" 구조. 네이버는 50 RPS·월 775,000 한도 안에서 10,000 상품 × 주 1회면 월 4~5만 건이라 한도는 충분(허용될 경우).
